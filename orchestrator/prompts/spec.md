# 工程: 要件整理・設計

Issue #{{ISSUE_NUMBER}} を読み、実装担当が迷わず作業できる仕様書を作ってください。
この工程ではアプリのコードは変更しません。

## 手順

1. `gh issue view {{ISSUE_NUMBER}} --comments` で Issue 本文とコメント（過去の質問への回答を含む）を読む。
2. `{{APP_DIR}}/` の既存コード、`docs/specs/` の既存仕様書を読み、現状を把握する。
3. `{{SPEC_PATH}}` に仕様書を書く。構成は次のとおり:
   - **背景・目的**
   - **スコープ**（やること / やらないこと）
   - **受け入れ条件**（チェックリスト形式。テストで検証できる粒度で書く）
   - **画面・振る舞い**（画面構成、状態遷移、エラー時の振る舞い）
   - **設計**（追加・変更するファイル、コンポーネント構成、状態管理、データ構造）
   - **テスト方針**（どの受け入れ条件をどのテストで確認するか）
   - **判断ログ**（Issue に書かれていなかったことをどう決めたか。選んだ案・却下した案・理由）
4. 新しいライブラリが必要なら、設計に理由と代替案を書く（追加は実装工程で行う）。
5. 仕様書をコミットして作業ブランチに push する:
   `git add {{SPEC_PATH}} && git commit -m "docs: #{{ISSUE_NUMBER}} の仕様書" && git push -u origin {{BRANCH}}`
6. Issue に、仕様書へのリンクと受け入れ条件の要約をコメントする。

## 最終結果

- 完了: `done`
- 質問を残して終了: `needs_clarification`
- 続行できないエラー: `failed`
