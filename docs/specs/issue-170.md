# Issue #170: 外国の著者や訳者がいると、作者が崩れる

## 背景・目的

#144 で作者の書き方をそろえる `app/src/lib/authorName.ts`（`normalizeAuthors`）を入れたが、次の入力で崩れる。

- 例: ISBN 9784274065972『ハッカーと画家』で「GrahamPaul1964-川合史朗」になる。
- 原因（コードから推定）: 元の値が「Graham, Paul, 1964- 川合, 史朗」のように **1 つの文字列に 2 人が空白だけで続く**。
  現在は (1) 生年が文字列の末尾にしかないものだけ取り除く、(2) 人の区切りを「役割語」でしか判定しない、(3) カンマで分けたあと、
  日本語が 1 文字でも含まれると全体を「日本人の名前」とみなして空白を詰める。このため 2 人が 1 人になり、「GrahamPaul」「1964-」が残る。
- 目的: タイトル検索（NDL: `parseNdlResponse.ts`）と ISBN（openBD: `OpenBdProvider.ts`）の両方で、同じ変換が行われ、崩れない作者になること。
  変換は両方とも `normalizeAuthors` を通るので、`authorName.ts` を直せば両方が直る。

## スコープ

やること
- `authorName.ts` の変換を直す（人の区切り、生年・没年の除去、人ごとの名前の整形）。
- 上記の書き方のテストを追加する。NDL・openBD のパーサーのテストにも『ハッカーと画家』相当のデータを追加する。

やらないこと
- 役割（著・訳）の表示、作者の構造化（配列）、カタカナ表記と原綴りの照合や併記。
- 取得先（NDL / openBD）や UI の変更。

## 受け入れ条件

`normalizeAuthors` / `normalizeAuthor` について（Jest）:

- [ ] 「Graham, Paul, 1964-」→「Paul Graham」
- [ ] 「Liu, Cixin」→「Cixin Liu」（生年なしの従来どおり）
- [ ] 「村上, 春樹, 1949-」→「村上春樹」、「村上／春樹」→「村上／春樹」でなく、**区切りの「／」は役割マークでなければ名前の一部として残す**現状の挙動（`姓／名` → `姓／名`）を変えない。
      ※ Issue の「村上／春樹」は、役割語が付かない「／」であり、現状のテスト（`姓／名`）に合わせて変えない（判断ログ参照）
- [ ] 生年・没年（「1964-」「1949-2020」「1867-1916」）が、文字列の末尾でも途中でも、どの書き方でも取り除かれる
- [ ] 「Graham, Paul, 1964- 川合, 史朗」→「Paul Graham、川合史朗」（今回の不具合の再現）
- [ ] 著者と訳者の 2 人（役割語あり: 「Graham, Paul／著 川合, 史朗／訳」）→「Paul Graham、川合史朗」
- [ ] 配列で渡された 2 人（`['Graham, Paul, 1964-', '川合, 史朗']`）→「Paul Graham、川合史朗」
- [ ] 著者が 3 人以上（空白区切り・配列・役割語つきのそれぞれ）→「、」でつながる。同じ名前は 1 つにする
- [ ] openBD の「ポール・グレアム／著 川合史朗／訳」→「ポール・グレアム、川合史朗」（中黒は残す）
- [ ] 日本人の作者の既存テストがすべてそのまま通る
- [ ] NDL のパーサー（`dc:creator` が 1 つの文字列に 2 人入っているデータ、2 要素のデータ）と openBD のプロバイダーで、同じ人物が同じ作者文字列になる
- [ ] 『ハッカーと画家』の実際の応答での確認結果を PR に書く（取得できない場合は、テスト用データでの確認と、その旨を書く）

## 画面・振る舞い

画面の変更はない。本の登録・編集の作者欄、検索結果の行に出る作者の文字列が変わるだけ。
変換できないもの（空、生年だけ）は従来どおり `null`（作者欄は空）。エラーは起こさない。

## 設計

変更ファイルは `app/src/lib/authorName.ts` と、そのテスト（`app/src/lib/__tests__/authorName.test.ts`）、
`app/src/lib/bookSearch/ndl/__tests__/` と `app/src/lib/bookLookup/__tests__/` の既存テスト（データ追加）。新しいライブラリは使わない。

処理の流れ（1 つの raw 文字列に対して）:

1. **生年・没年の除去を先に行う**: `\d{4}-(\d{4})?` を、位置にかかわらず取り除く（前後のカンマ・空白も整理）。
   このとき人の区切りとして扱うため、取り除いた位置に区切り記号を入れる（下の 2.）。
2. **人の区切り**: 次のいずれかで 1 つの文字列を複数人に分ける。
   - 役割語の直後（現行どおり）
   - 生年・没年の直後（「Graham, Paul, 1964- 川合, 史朗」の「1964-」のあと）
   - 「姓, 名」の組が続く場合: カンマで分けた要素を、先頭から「姓, 名」の 2 要素ずつ組にする。ただし、
     生年や役割語で区切られていない文字列が「A, B, C, D」のように偶数個で、各要素が空白を含まない場合に限る
     （要素数が奇数、または空白を含む要素があるときは区切りを推測せず、現行のとおり 1 人として扱う）。
3. **人ごとの整形**（`normalizePerson`）: 「姓, 名」のカンマ区切りを人ごとに判定する。
   - 日本語（かな・漢字）が含まれる人は、その人の部分だけで空白を詰めて「姓名」にする。
     **日本語判定は文字列全体でなく、人ごとに行う**（これが「GrahamPaul」の直接の原因）。
   - 日本語を含まない人は「名 姓」の順（`Paul Graham`）。カンマがなければそのまま。
4. 複数人は「、」でつなぎ、同じ名前は 1 つにする（現行どおり）。

2.（人の区切り）の「姓, 名」を 2 要素ずつ組にする規則は誤判定の恐れがあるので、実装では
「生年・役割語・配列の要素の境界」で分けることを優先し、組にする規則は、この 3 つで分けられなかった場合の補助にとどめる。
実装担当は、テストで受け入れ条件の全ケースが通る最小の形にしてよい（補助規則が不要なら入れない）。

## テスト方針

| 受け入れ条件 | テスト |

| 変換のすべての書き方（外国人、日本人、生年、2 人、3 人以上、openBD の形） | `authorName.test.ts` の `it.each` に追加 |
| 同じ人物が NDL と openBD で同じ文字列 | `authorName.test.ts` の 1 ケースと、NDL パーサー・openBD プロバイダーの既存テストにデータ追加 |
| 既存の日本人の作者 | 既存テストをそのまま残す |

## 判断ログ

- **役割（著・訳）を付けるか**: 付けない。作者欄は 1 行の文字列で、既存の挙動（役割は取り除く）と一貫させる。却下: 「Paul Graham（著）」の形。理由: 作者欄が長くなり、検索・並び替えでも邪魔になる。
- **カタカナ表記がある場合**: 取得した表記をそのまま使い、原綴りとの照合や併記はしない（openBD の「ポール・グレアム」は中黒を残して「ポール・グレアム」）。却下: 原綴りへの変換。理由: 根拠となるデータが応答にない。
- **「村上／春樹」**: 役割語のつかない「／」は名前の一部として残す（既存テスト `姓／名` と同じ）。「／」を役割語の有無にかかわらず区切りにすると「姓／名」の既存の振る舞いを変える。Issue の「村上／春樹」は、既存の挙動のまま「村上／春樹」として確認する。
  ※ 実際の NDL・openBD で「／」が姓名の区切りに使われる例が確認できた場合は、別 Issue にする。
- **実データの確認**: 元の値は推定（Issue 本文）。実装担当は実際の応答を取得できれば、その値でテストデータを作る。取得できないときは、推定した値でテストし、PR にその旨を書く。
- **人の区切りの推測**: 偶数個のカンマ要素を勝手に組にする規則は誤判定の恐れがあるので、補助にとどめる（設計の 2.）。
