# Issue #123 見た目を直す: 読み返す

## 背景・目的

#107 の続き。`RereadScreen`（読み返す）を `docs/design-system/screens/reread.png` と見比べて直す。`cd app && pnpm shots -- reread` で今の画面を撮り（`app/.screenshots/`）、画像と見比べる。画像と部品 README が食い違うときは部品 README を優先する。色・余白・角丸・文字は `design/tokens.ts` のトークンで直し、画像から数値を読まない。画像の本・作者・文章はサンプルなので中身の違いは直さない。

2026-10-27 の動作確認（main `3043694`、Web 版）で Issue に挙がった差を出発点にする。読みたい本の画面（読み始める操作）は #137 なのでここでは扱わない。

## スコープ

### やること

実装担当は撮影して「確認する項目」を1つずつ見比べる。「差の候補」は Issue の指摘と現行コード・画像からの推測。撮って確かめ、違わなければ「一致」とする。ここに無い差も見つけたら直す。

| 項目 | 差の候補 | 直す方向 |
|---|---|---|
| 戻るボタン | `Button variant="icon"` で丸い背景（`surface2`）つき。画像は背景なしの「‹」だけ | 背景なしにする。`touchMin`（44）以上のタップ領域と `accessibilityLabel="戻る"` は保つ。「‹」は文字の大きさを画像に合わせる。`Button` の `icon` を直すと他画面が変わるので、`Pressable` をこの画面で使うか、`Button` に背景なしの種別を足すかは実装担当が決め、後者なら使う他画面も撮る |

### やらないこと
- `tokens.ts` / `docs/design-system/` / CI 設定の変更。トークンに無い色・文字スタイル・部品が要るときは判断ログに提案する
- 読みたい本の画面（#137）、文言の変更、`lib/reread.ts` の並び順・期間の書式の変更（期間が出ない原因が別にある場合を除く）
- 読み返す以外の画面の見た目の変更。共通部品（`Button`、`MemoRow`、`StarterText`、`RatingStars`）を直して他画面が変わる場合は、その画面も `pnpm shots` で撮って確かめ、PR に書く
- 新しい依存の追加（不要）

## 画面・振る舞い

- 上から: 戻る「‹」（左、背景なし）と「編集」（右）→ タイトル → 作者 · 期間 → ひとこと（「」付き）→ 星・数字・言葉（左）とお気に入りのラベル（右）→ 区切り線 → 書き出しの続き・引用・自由記述（書いた順、本文は罫線つき）→ 区切り線 → 「メモ」とメモ（ページ順）→ 区切り線 → 本棚・書き出しの続きを書く。
- 内容がない項目・セクションは見出しごと出さない。何も書いていない読み終えた本は案内とボタン（既存）。
- 読み込み中・見つからない・保存失敗の振る舞いは変えない。

## 判断ログ

- **画像と README の優先**: 食い違うときは部品 README を優先する（#122 と同じ方針）。
- **罫線の実装**: 画像は各行の下に線が引かれている。Web / iOS / Android で動く方法を実装担当が選ぶ。選んだ案と却下した案はこの欄か PR 本文に書く。引用には罫線を付けない（画像は引用の左の朱の線だけ）。
- **お気に入り・期間の「差」は推測**: Issue は「文字だけに見える」「終えた日だけになる」と書くが、現行コードは枠つきの `pill` と、両日あれば範囲を出す `buildRereadPeriod` を持つ。コードの読みだけでは原因を断定できないため、撮影で再現を確かめてから直す。再現しなければ「一致」として表に書く（実データの `startDate` が保存されていない可能性も確認する）。
- **戻るボタンの直し方**: `Button` の `icon` 種別は他画面で使われているため、まず `RereadScreen` 内で背景なしにする案を優先する。他画面の戻るも画像が背景なしなら、別 Issue で揃える提案を PR 本文に書く。
- **質問は不要と判断**: 差の項目はすべて画像・README・トークンで決められるため、Issue への質問なしで進める。
