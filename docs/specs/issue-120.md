# Issue #120 見た目を直す: 本を登録・編集

## 背景・目的

本を登録・編集する画面（`RecordForm`）が `docs/design-system/screens/book-form.png` と違う。`pnpm shots -- book-form` で今の画面を撮り（`app/.screenshots/`）、デザイン画像と見比べて違いを直す。画像と部品の README が食い違うときは部品の README を優先し、色・余白・角丸・文字は `design/tokens.ts` のトークンで直す。画像の本・作者・文章（サンプル）の違いは直さない。

## スコープ

### やること
仕様書作成時に画像と README とコードを読んで見つけた差。実装担当は撮影して確かめ、下に無い差も Issue の「確認する項目」を1つずつ見て、見つけたら直す。

| 項目 | 今の画面 | 直す方向 |
|---|---|---|
| 背表紙プレビュー・色の丸 | 丸 28px、選択中の枠が `accent` 2px で丸に密着 | 画像は選択中の丸の外側に墨の輪（丸との間に隙間）。丸の間隔を詰める（タップ領域 44px は `hitSlop` か透明な外側で保つ）。プレビューの背表紙の下端を「背表紙の色」の注記の下端と揃える |
| 入力欄（`TextField`） | 枠・角丸・高さ・見出しの太さ | README: 面 `surface-1`、枠 `line`、角丸 10〜12、高さ `button-height`、見出し `label` 太字・`textSecondary`、必須は「（必須）」。出版社と ISBN の欄の高さが揃っていない（ISBN は 56px で大きい）ため、フォームでは同じ高さにそろえる（ISBN の文字は画像どおり通常の大きさ） |
| ステータス（`ChipGroup`） | 2 列の幅広グリッド、枠 `lineStrong`、角丸 10、文字 `label`・`textSecondary` | Chip README: 横に並べて折り返す丸いチップ（角丸 `radius-full`、高さ 36、左右 14、文字 `value`、未選択の枠 `line`・文字 `textPrimary`）。`Chip` は他の画面でも使うため、変えたら影響画面（設定の「一度に出す数」、読み返す画面など）も撮って確かめる |

| 余白・セクション間隔 | `space[5]` の gap | 画像と見比べ、見出し→入力欄の間、セクション間をトークンで調整 |

### やらないこと
- `tokens.ts` / `docs/design-system/` / CI の変更。トークンに無い色・文字スタイルが要るときは判断ログに提案を書く
- 画面ヘッダー（キャンセル・タイトル）の変更（画面のルーティング側の領域。違いがあれば判断ログに記録のみ）
- 保存・検証・削除・日付ロジックの変更（見た目だけ）
- `ShelfPickSheet` を他の画面から使っている場合の削除。フォームから使わなくなっても、他で使われていれば残す（使われなくなるなら、削除でなく残して判断ログに書く）

## 受け入れ条件

- [ ] 背表紙のプレビューと「背表紙の色」の丸が出る。選んだ丸が `selected` / `checked`、押すと色が変わりプレビューに反映（既存の振る舞い）
- [ ] 「タイトル（必須）」「作者」「出版社」「ISBN」の入力欄が、アクセシビリティ名・ラベルを変えずに出る。タイトルが空のまま保存するとエラーが出る（既存）
- [ ] ステータスの 4 つのチップが出て、選択中が `checked`、押すと切り替わる。切り替えで日付が変わる既存の振る舞いを保つ
- [ ] 読み始めた日・読み終えた日が出る。押すと日付の選択シートが開く。未入力は「—」

- [ ] 「＋ 本棚を作る」を押すと作成シートが開き、作ると新しい本棚がチップに加わり選択される
- [ ] 「「すべての本」にはいつも入ります」が出る
- [ ] 追加は「棚に並べる」、編集は「保存する」のボタンが出る。保存中は無効
- [ ] 編集のときだけ「この本を削除」が出て、押すと確認シートが開く。追加では出ない
- [ ] `Chip` を直した影響で、他の画面のチップ（ラベル・ロール・選択状態）の既存テストが通る
- [ ] 撮り直した `book-form`（追加用と編集用の両方）を画像と見比べ、PR 本文に「確認する項目」の全項目について 一致 / 直した / 残した（理由）の表を書く
- [ ] `cd app && pnpm check` が通る

## 画面・振る舞い

上から、背表紙のプレビュー＋「背表紙の色」の丸＋注記、タイトル、作者、出版社と ISBN（横に 2 つ）、ステータスのチップ、読み始めた日と読み終えた日（横に 2 つ）、本棚のチップと説明、（編集のみ）「この本を削除」。下に固定の主ボタン。状態遷移・エラー時の振る舞いは変えない。

本棚のチップ: 押すと選択を切り替える。「＋ 本棚を作る」は選択ではなく作成シートを開く。作成に成功したらその本棚を選択状態にする。作成に失敗したときは既存の `useShelfPick.create` / `ShelfCreateSheet` のエラー表示に従う。

## 設計

変更するファイル（`app/src/`）:
- `components/RecordForm.tsx` — 本棚を `ChipMultiGroup` + 点線チップ + 説明に置き換え、`ShelfCreateSheet` を使う。余白・ISBN と出版社の高さ
- `components/Chip.tsx` — Chip README に合わせる（角丸・高さ・文字・枠）。`ChipMultiGroup` を本棚のチップで使えるようにし、点線の「＋ 本棚を作る」は `ShelfChips` の同名部品があれば共通化（なければ `RecordForm` 内に作る）
- `components/SpineColorPicker.tsx` — 選択中の輪
- `components/TextField.tsx` — 入力欄・日付欄の形（README に合わせる）。`variant="isbn"` の高さはフォーム内で揃える（他で ISBN を使う画面は撮って確かめる）
- `components/Button.tsx` — 必要なときだけ
- `scripts/screenshots/scenes.cjs` — 追加用の `book-form` シーン（画像は追加画面）を撮れるようにする。例: 既存の `book-form` は編集のままにして、追加用に `book-form-new`（`/record/new` 相当の URL、本棚 3 つ）を足す。シードが `recordGuard` を通ること（既存テスト）を保つ

状態管理・データ構造の変更なし（`values.shelfIds` は既存）。**依存の追加なし。**

## 判断ログ

- **本棚の選び方を画像どおりのチップにするか**: 変える。画像・画面の README とも「本棚（`Chip` 複数選択）」で、Chip README も本の登録画面の本棚は複数選択のチップと明記している。却下案: 今のシート方式を残す（画像との差が最大の項目として残る）。副作用として本棚が多いとフォームが縦に伸びるが、チップは折り返すので許容する。
- **Chip README と画像の食い違い**: 画像は未選択の文字が太い（`value`）、README は未選択の文字を `textPrimary`。README を優先する（Issue の方針）。
- **日付の説明文（`getDateHint`）**: 画像に無いが、機能の説明なので残す。却下案: 削除（入力のヒントが失われる）。
- **画面ヘッダー（「キャンセル」「本を登録」）**: Issue の確認項目に含まれないので、このスコープでは変えない。
- **追加用の撮影シーン**: 画像は追加画面、既存シーンは編集画面。両方撮れるようシーンを足す（`book-form-new`）。
