# Issue #174 読み返す画面で、読みながら書いた引用・メモを1つの段にまとめ、ページ順に並べる

## 背景・目的

読み返す画面（`RereadScreen`）では、書き出しの続き・自由記述・引用が書いた日時順に混ざり、メモだけが下の「メモ」の段にページ順で出る。
同じ読書中に書いた引用とメモが別の場所に分かれ、読後の感想と引用の前後関係も分かりにくい。
読後に書いたもの（感想）と、読みながら書いたもの（引用・メモ）を段で分け、後者を読んでる本の画面と同じ並びにする。

## スコープ

やること
- `buildRereadEntries` から引用を外し、書き出しの続き・自由記述だけを書いた順に返す
- 「読みながら」の段を作り、引用とメモを `buildNoteItems` のページ順で `Quote` / `MemoRow` で表示する
- 「＋ メモ・引用を書く」を「読みながら」の段に置く（タップして直す・削除は現状どおり）
- テスト更新、`pnpm shots -- reread` の撮影用データに読書中の引用・メモと読後の書き出しを入れる（`app/scripts/screenshots/` 側。ガード対象外の場合のみ）

やらないこと
- 何も書いていない本の案内、振り返り（`review.ts`）の集計（感想・引用の数）の変更
- `docs/design-system/` の更新（人間が行う）
- 読んでる本の画面の変更

## 受け入れ条件

- [ ] 読書中の引用・メモ、読後の書き出しの続き・自由記述、あとで足した引用・メモを持つ本で、上から「ひとこと → 感想（書き出しの続き・自由記述、書いた順）→ 読みながら（引用とメモ、ページ順）」の順で表示される
- [ ] 「読みながら」の並び（ページ昇順、ページなしは最後、同ページは書いた順）が、読んでる本の画面の「メモと引用」と同じ。同じテスト用データで両画面の表示順を比べる
- [ ] 感想の段に引用が出ない（引用は「読みながら」の段にだけ出る）
- [ ] 「読みながら」の見出しは「メモと引用」、右に `N 件`（引用+メモの数）。読んでる本の画面と同じ書式
- [ ] 「読みながら」の段に「＋ メモ・引用を書く」があり、押すと NoteSheet が開く。引用・メモをタップして直す・削除できる
- [ ] 本が読みたい（planned）のとき、メモ・引用がなければ「読みながら」の段・追加ボタンを出さない（現状のメモの段と同じ条件: `status !== 'planned'` か、メモ・引用が1件以上）
- [ ] 感想が空なら感想の段（と上の区切り線）を出さない
- [ ] 何も書いていない読了本の案内は従来どおり出る（引用・メモだけの本では出ない）
- [ ] `buildRereadEntries` は引用を返さない。`hasRereadContent` は引用・メモのみでも true

## 画面・振る舞い

上から: ヘッダー、BookHero、ひとこと、評価行、区切り線、
**感想**（見出しなし。`RuledText` に書き出しの続き・自由記述を書いた順。0件なら段ごと省略）、区切り線、
**メモと引用**（`sectionHead` = 見出し + `N 件`、`buildNoteItems` の並びで `Quote`/`MemoRow`、0件で追加可能なら読んでる本の画面と同じ空文言「まだ何もありません。気づいたことを、ひとこと残してみませんか」、「＋ メモ・引用を書く」）、
空の案内、読み始めるの案内、本棚、書き出しの続きを書く。
エラー時の振る舞いは現状どおり（NoteSheet の保存失敗は NoteSheet 内）。

## 設計

- `app/src/lib/reread.ts`: `RereadEntry` から `quote` を外し `RereadSource` を `starters | freeTexts` に。`hasRereadContent` は `quotes` を別途判定に加える（引用が空文字のみなら除外）。
- `app/src/screens/RereadScreen.tsx`:
  - `memos`/`sortMemos` をやめ、`noteItems = buildNoteItems` を、本文が空でないものに絞った record で作る（`{memos: filter, quotes: filter}`）。
  - 感想の `entries` の描画から quote 分岐を削除。
  - 「メモ」の段を「メモと引用」の段に置換。見出しは ReadingScreen と同じ `sectionHead` スタイル（ReadingScreen の style を参考に同値で定義）。`sortMemos` が他で未使用になれば import を外す（関数自体は残す）。
- 新規依存なし。

## テスト方針

- `lib/__tests__/reread.test.ts`: 引用が出ない・書いた順（受け入れ: 感想に引用なし、`hasRereadContent`）
- `screens/__tests__/RereadScreen.test.tsx`: 段の順序、ページ順（ページなし最後・同ページは書いた順）、感想に引用なし、見出し・件数、追加ボタン位置と編集/削除、planned の条件、空案内
- 並びの一致: 同じ record を RereadScreen と ReadingScreen に表示し、`Quote`/`MemoRow` の本文の出現順が一致することを確認（`ReadingScreen.test.tsx` か Reread テスト内で両方 render）
- 既存の引用が混ざる前提のテストは新仕様に更新する（削除ではなく書き換え。判断ログに記載）

## 判断ログ

- 見出しの言葉: 「メモと引用」を採用（Issue が許容、読んでる本の画面と同じで学習コストなし）。「読みながら」は却下（画面間で語が揺れる）。
- 感想の段の見出し: Issue どおり付けない。
- 引用の空文字除外: 既存の `buildRereadEntries` が空本文を除いていたため、引用・メモも空本文を除く現状維持の挙動にした。
- 区切り線: 感想が空のときは感想の段ごと省略し、線が二重にならないようにする。
- メモの段を出す条件は現状（`noteable || memos.length>0`）に引用を加えただけにした。
- デザイン画像 `reread.png` / README「読み返す」は書き出しの続きと引用が同じ流れ。Issue の並べ方を優先し、差分は PR 本文に書く。README の更新は人間が行う（提案: 「ひとこと → 感想 → メモと引用（ページ順）」に直す）。
- 撮影（`pnpm shots -- reread`）のデータ変更が保護対象のファイルにある場合は、実装担当が PR 本文に人間の作業として書く。
