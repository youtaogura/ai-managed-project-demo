# Issue #21 ISBNで探すページなど、ヘッダーがないページがある

## 背景・目的

Issue 本文は空で、タイトルのみ「ISBNで探すページなど、ヘッダーがないページがある」。
ナビゲーションヘッダー（タイトル・戻るボタン）が表示されない画面があり、戻る操作や画面の把握ができない。すべての画面で、意図したヘッダーが表示される状態にする。

現状（コード調査）:
- `src/app/_layout.tsx` のルート `Stack` は既定 `headerShown: false` で、画面ごとに `Stack.Screen` の `name` で `headerShown: true` を上書きしている（`records/[id]` `record/new` `record/isbn` `record/[id]`）。`(tabs)` は `Tabs` 自身のヘッダー。
- この方式は `name` がルート名と一致しないと上書きが黙って無視され、既定の `headerShown: false` のままになる。ISBN で探す画面（`record/isbn`）などで発生している可能性が高い。
- `record/scan`（バーコード読み取り）は意図的に `headerShown: false` で、#18 で `ScreenContainer` により上端インセットを自前で確保している。そのためヘッダーも戻る手段もキャンセルボタンだけになっている。
- 実機・開発サーバーが使えないため、どの画面でヘッダーが出ないかは実装工程でルーター結合テスト（`renderRouter`、実ルートのコンポーネントを使用）で再現して特定する。

## スコープ

### やること
- ルート画面すべて（記録一覧・分析タブ、記録の詳細・追加・編集、ISBN で探す、バーコード読み取り）でヘッダーが表示されることをルーター結合テストで保証する。
- ヘッダーが出ない画面があれば原因を特定して修正する。
- ヘッダー設定を画面側（各ルートコンポーネント内の `Stack.Screen options`）に置くか、ルートレイアウトの `name` が実在ルートと一致する形に直し、名前の不一致で黙って無効化されない構成にする。
- バーコード読み取り画面にもヘッダー（タイトル「バーコードを読み取る」、戻るボタン）を表示する。

### やらないこと
- ヘッダーのデザイン変更、ナビゲーション構成（Tabs / Stack）の変更
- 新しいライブラリの追加（依存追加なし）
- 既存のタイトル文言の変更

## 受け入れ条件

- [ ] 実ルート（`record/isbn` `record/new` `record/[id]` `records/[id]` `record/scan`）を `renderRouter` で描画し、それぞれ遷移先でヘッダータイトルが表示される: 「ISBN で探す」「記録を追加」「記録を編集」「記録の詳細」「バーコードを読み取る」
- [ ] 記録一覧（「記録一覧」）と分析（「分析」）タブのヘッダーが表示される（既存挙動の維持）
- [ ] 記録一覧の「ISBN で探す」ボタンから `/record/isbn` に遷移すると、ヘッダー付きで ISBN 入力画面が表示される
- [ ] バーコード読み取り画面にヘッダーが出るため、`ScreenContainer` による上端余白は二重にならない（上端インセット top=47 の環境でコンテンツ先頭の余白が top 分増えない）。画面の操作（キャンセル・手入力へ切替・読み取り）は従来どおり動く
- [ ] 上端インセット 0 の既定テスト環境で既存テストがすべて通る
- [ ] `pnpm check` が通る（カバレッジ・差分カバレッジを満たす）

## 設計

1. **原因特定（先にテスト）**: `src/__tests__/headers.test.tsx`（新規）で、実ルートコンポーネントを使った `renderRouter` から各画面へ遷移し、ヘッダータイトルを検証する。ヘッダーが出ない画面があればこのテストが先に失敗するので、それを確認してから直す。カメラ・AsyncStorage・書誌検索はモック（既存の `BarcodeScanScreen.test.tsx` `IsbnLookupScreen.test.tsx` の方式に合わせる）。
2. **ヘッダー設定の置き場所**: 各ルートファイル（`src/app/record/isbn.tsx` など）で `expo-router` の `Stack.Screen options={{ headerShown: true, title: ... }}` を描画する。ルート `_layout.tsx` は `screenOptions={{ headerShown: true }}` を既定にし、`(tabs)` のみ `headerShown: false`（Tabs 側ヘッダーを使うため）にする。名前文字列に依存する個別 `Stack.Screen` 列挙は、タイトルをルート側に移すことで不要になれば削除する。
3. **バーコード画面**: `src/app/_layout.tsx` / ルートでヘッダーを表示するようにし、`BarcodeScanScreen` の `ScreenContainer` ラップを外す（ヘッダーがインセットを処理するため二重余白を避ける）。`ScreenContainer` コンポーネントはほかで未使用になる場合も、#18 のテストがあるため削除せず残す（削除するなら対応テストも整理し、判断ログに記録）。
4. 色・余白は `src/theme.ts` の既存定数を使う。状態管理・データ構造の変更なし。

## 判断ログ

- **Issue 本文が空**: タイトルから「ヘッダーが出ない画面を、ISBN で探す画面に限らず全画面で解消する」と解釈した。質問しても方針（全画面でヘッダーを保証）は変わらず手戻りが小さいため `needs_clarification` にはしない。
- **原因の扱い**: 実機確認不可のため原因は断定せず、先に失敗するテストで再現する方針。再現しない画面は変更せず、PR 判断ログに「再現せず」と記録する。
- **案 A（採用）**: ヘッダー設定を各ルート側（`Stack.Screen options`）に置き、ルート既定を `headerShown: true`、`(tabs)` のみ非表示。名前の不一致で黙って無効化される問題を構造的に避けられる。
- **案 B（却下）**: ルートの `Stack.Screen name=...` 列挙のまま名前だけ直す。再発しやすく、原因が名前以外の場合に効かない。
- **案 C（却下）**: 各画面コンポーネント内に自前のヘッダー View を作る。標準の戻るジェスチャ・ボタンやインセット処理を再実装することになる。
- **バーコード画面にヘッダーを付ける（採用）**: タイトルのみ付けた標準ヘッダーで戻る手段が増え、Issue の趣旨（ヘッダーがない画面をなくす）に合う。全画面カメラ表示の没入感は下がるが、カメラ領域は残りの領域に表示される。却下案: ヘッダーなしのまま維持（Issue の趣旨に反する）。
- **新規ライブラリなし**。
