# Issue #125 見た目を直す: 設定・書き出しの管理

## 背景・目的

設定（`SettingsScreen`）と書き出しの管理（`StartersScreen`）が `docs/design-system/screens/settings.png` / `starters.png` と細かく違う。`cd app && pnpm shots -- settings starters` で今の画面を撮り（`app/.screenshots/*.png`）、デザイン画像と見比べて違いを直す。画像と部品の README が食い違うときは部品の README（`Toggle` `Chip` `TabBar`）を優先し、色・余白・角丸・文字は `design/tokens.ts` のトークンで直す。画像の中身（件数、書き出しの文、日付）の違いは直さない。#107（撮影の仕組み）、#117（本棚の見た目）は main にマージ済み。

## スコープ

### やること

この工程では撮影できない（アプリを起動しない）ため、画像と現行コードの読み合わせで「差の候補」を挙げる。実装担当は撮って違いを確かめてから直す（違わなければ「一致」。下に無い差も見つけたら直す）。

**設定**

| 項目 | 差の候補（現行コード） | 直す方向 |
|---|---|---|
| 見出し「設定」 | `screenTitle`、`paddingVertical: space[3]` | 画像と余白・位置を比べる |
| セクション見出し（読み終えたら／本棚） | `SettingsCard` の `label`、`textSecondary`、カードとの間は `space[2]` | 文字スタイル・見出しとカードの間・左端の揃えを比べる |
| カードの行（2行目の説明、右の矢印） | `SettingsRow`: 項目名 `body`、値 `label`、`›` はテキスト | 2行目の文字サイズ・色、矢印の色・大きさ、行内の余白を比べる |
| 最後のカード（データ、このアプリについて） | 見出しなしのカード。「データ」の2行目は「書き出し・読み込み · 最後に書き出した日 …」 | 見出しなしの余白、2行目の文言（画像と違えば、画面の言葉として自然な方を残す） |
| 行の高さ・区切り線・カードの角丸と枠 | `size.touchMin` 以上、`line` の区切り、`radius.card`、`surface1` | 画像と比べ、違えば `size`/`radius`/`space` から選ぶ |

**書き出しの管理**

| 項目 | 差の候補 | 直す方向 |
|---|---|---|
| 「読み終えたら書き出しを出す」のトグル | `ToggleRow`（ラベル太字、説明 `micro`）。トラック 51×31、オン＝朱 | `docs/design-system/components/Toggle/README.md` と比べる（色・大きさ・ラベルの太さ）。部品を直して他画面が変わるときは、使っている画面も撮る |
| 「一度に出す数」（2・3・5 のチップ） | `ChipGroup` を `maxWidth: 200` の枠に入れて右寄せ | 画像のチップの幅・並び・選択中の色を `Chip` の README と比べる |
| 書き出しの一覧（明朝）とトグル、「固定」「自分で追加」の印 | `starter` 変数の明朝、`Badge`（`micro`）、行の下罫線、小トグル | 行の高さ・区切り線（最後の行の罫線）・印の形（枠線か地色か）・オフの文字色を比べる |
| 「＋ 自分の書き出しを追加」 | `Pressable` + `button` 文字、`textSecondary` | 点線の枠・中央寄せなど画像の形を比べる。`Chip` の `DashedChip` の流用が合えば使う |

### やらないこと
- `tokens.ts` / `docs/design-system/` / CI の変更。トークンに無い色・文字スタイル・部品が要るときは判断ログに提案する
- データ・書き出し・読み込み・削除・このアプリについて・ライセンスの画面（画像なし）。ただし `SettingsCard`/`SettingsRow` を直すと `DataScreen` `AboutScreen` も変わるので、その場合は `pnpm shots` では撮れないため、変更が見た目の微調整にとどまることをコードで確認し PR 本文に書く
- 設定値・書き出しの選び方などのロジック、文言（画面の言葉）の変更。見た目だけ
- 共通部品を直して他画面が変わる場合（`Toggle` は `RecordFormScreen` 等、`Chip` は本棚など）は、その画面も撮って確かめ、PR 本文に書く。基本は部品でなく画面側で直す

## 受け入れ条件

設定
- [ ] 見出し「設定」と、セクション見出し「読み終えたら」「本棚」が表示される
- [ ] 行「書き出し」（2行目 `starterSummary`）、「ステータスの初期値」（2行目に現在の値）、「本棚の管理」（2行目に「まだありません」または「N つ」）、「並び順」（2行目に現在の並び順）が表示され、各行に矢印がある（スクリーンリーダーには隠す）
- [ ] 最後のカードに「データ」（2行目に最後に書き出した日、なければ「まだ書き出していません」）と「このアプリについて」が出る
- [ ] 各行をタップすると、対応するコールバック（`onOpenStarters` `onOpenShelves` `onOpenData` `onOpenAbout`）が呼ばれるか、シート（ステータスの初期値・並び順）が開く（既存の振る舞い）

書き出しの管理
- [ ] 「読み終えたら書き出しを出す」のトグルが現在の設定を反映し、押すと切り替わる
- [ ] 「一度に出す数」に 2・3・5 のチップが出て、現在の数が選択状態。押すと変わる
- [ ] 「ひとことで言うと、」が「固定」の印つきで出て、トグルは操作できない（オン固定）
- [ ] 一覧の各書き出しにトグルがあり、押すとオン／オフが切り替わる。自分で足したものには「自分で追加」の印が出て、タップすると編集シートが開く
- [ ] 「＋ 自分の書き出しを追加」で追加シートが開き、追加・名前の変更・削除ができる（既存の振る舞い）

共通
- [ ] 画像と見比べ、PR 本文に画面ごとの「確認する項目」（Issue の全項目）について 一致 / 直した（何をどう）/ 残した（理由）の表を書く。撮り直して確かめたことも書く
- [ ] 他画面の見た目を変えない（部品を直した場合は影響画面を撮って PR に書く）
- [ ] `cd app && pnpm check` が通る

## 画面・振る舞い

設定: 上から見出し「設定」、カード3つ（「読み終えたら」「本棚」、見出しなしの最後のカード）。縦スクロール、下にタブバー。
書き出しの管理: ヘッダー「書き出し」（閉じる）、トグルのカード、「一度に出す数」＋チップ、「出す書き出し」の見出し、一覧（固定の1行＋各項目）、「＋ 自分の書き出しを追加」。シート（追加・編集・削除確認）は既存どおり。状態遷移・エラー時の振る舞い（同名の書き出しは作れない等）は変えない。

## 設計

変更しうるファイル（すべて `app/` 配下。撮影の結果で絞る）:
- `src/screens/SettingsScreen.tsx`、`src/components/SettingsCard.tsx`、`src/components/SettingsRow.tsx` — 余白・文字・矢印・区切り
- `src/screens/StartersScreen.tsx` — カード・チップ行・一覧行・印・追加ボタンの見た目
- `src/components/Toggle.tsx`、`src/components/Chip.tsx` — README と違うときだけ（影響画面も撮る）
- `scripts/screenshots/scenes.cjs` — `starters` シーンが `data: () => ({})` で、画像のような「自分で追加」の項目や、オン・オフ混在の一覧を撮れない。`starterSettings`（`STORAGE_KEYS.starterSettings`）を渡して、画像と同じ状態（オン、一度に 3 つ、自分で追加が1件、オフが混在）を撮れるようにする。`settings` シーンも、「ステータスの初期値」「最後に書き出した日」など画像と同じ表示になるようデータを足す。シードが既存のスキーマ検証を通ること（既存のシーンのテストを保つ）

状態管理・データ構造の変更なし。**パッケージの追加なし。**

## テスト方針

| 受け入れ条件 | テスト |
|---|---|
| 設定の見出し・セクション・行・2行目・矢印・タップ | `screens/__tests__/SettingsScreen.test.tsx`、`components/__tests__/SettingsRow.test.tsx`（既存を、変更した構造に合わせて更新） |
| トグル・チップ・固定・印・追加／編集 | `screens/__tests__/StartersScreen.test.tsx`（既存を更新。追加した表示の出し分けは足す） |
| `Toggle` / `Chip` を変えた場合 | `components/__tests__/Toggle.test.tsx` / `Chip.test.tsx` |
| シーンのデータ | `scripts/screenshots` の既存テスト |

スタイルの数値だけのテストは足さない。変更行の差分カバレッジ 80% 以上。テストを削る場合は PR 本文の判断ログに理由を書く。

## 判断ログ

- **差を仕様段階で確定しない**: 撮影できないため、コードの読み合わせによる候補を挙げ、確認は実装担当の撮影に委ねる。却下案: 推測した数値を仕様に固定する（誤りで手戻りになる）。
- **共通部品より画面側で直す**: `Toggle`/`Chip` は他画面でも使う。README と食い違うときだけ部品を直し、その場合は影響画面を撮る。却下案: 先に部品を作り直す（他画面の見た目が変わる範囲が大きい）。
- **`SettingsCard`/`SettingsRow` は DataScreen・AboutScreen と共用**: 画像のない画面は見た目だけ書斎のトークンに合わせる方針（screens/README）。部品を直して波及する場合は、波及をコードで確認して PR に書く。
- **撮影データの追加**: `starters` が空データでは「自分で追加」の印・オフの行を撮れず、項目を比べられないため、`scenes.cjs` にシードを足す（Issue の「進め方」4 に沿う）。
- **ライブラリ・トークンの追加なし**。新しい色・部品が要るときは実装担当がここに提案を追記する。
