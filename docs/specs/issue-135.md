# Issue #135 ステータスを変えても日付が残り、読みたい・読んでる本が「今年読んだ」に数えられる

## 背景・目的

登録・編集フォームでステータスを切り替えても、一度入った日付が消えない（`applyStatusChange` は日付を入れるだけ）。
そのため「読みたい」「読んでる」の本に読み終えた日が残る。さらに本棚の「今年読んだ N 冊」（`countCompletions`）はステータスを見ずに終えた日だけで数えるので、読みたい・読んでる・途中でやめた本まで数えてしまう。
日付とステータスを矛盾させず、「今年読んだ」を振り返り（`review.ts`）・月別集計（`analytics.ts`）と同じ「読み終わった本だけ」の数え方にそろえる。

## スコープ

やること
- ステータス切り替え時に、そのステータスに合わない日付を空にする（フォーム: 登録・編集共通）
- `countCompletions` を、ステータスが `completed` の記録だけ数えるようにする
- 日付の説明文（`getDateHint`）を、選択中のステータスに意味のあるものだけ出す

やらないこと
- すでに保存された誤った日付の移行（未リリースのため不要）
- `ReadingScreen` の「読み終えた」ボタンの挙動変更（`completed` にして終えた日を今日にする、は今のまま）
- 保存時（`toInput`）や `recordGuard` での日付の強制クリア（フォーム操作側で整合させる。既存データの読み込みは壊さない）
- 振り返り・月別集計の変更（すでにステータスを見ている。ただし回帰テストは確認する）

## 受け入れ条件

- [ ] `applyStatusChange` で `planned` にすると、読み始めた日・読み終えた日が両方空になる
- [ ] `applyStatusChange` で `in_progress` にすると、読み始めた日が空なら today、入っていればそのまま。読み終えた日は空になる
- [ ] `applyStatusChange` で `completed` / `dropped` にすると、読み終えた日が空なら today（今までどおり）。入っていればそのまま。読み始めた日は変えない
- [ ] 手で入力する新規登録で、初期ステータス「読み終わった」→「読んでる」に変えると、読み終えた日が空・読み始めた日が today になる。「読みたい」に変えると両方空になる（RecordForm の Jest）
- [ ] 編集画面で「読み終わった」→「読んでる」に変えて保存すると、保存された記録の `endDate` が `null` になる（Jest）
- [ ] 「読みたい」「読んでる」「途中でやめた」の記録は `countCompletions` の year・month に数えられない（終えた日が今年・今月でも）
- [ ] 「読み終わった」で終えた日が今年の記録だけ year に、今月の記録だけ month に数えられる。終えた日が null の `completed` は数えない
- [ ] 本棚の見出しが、読んでいる本・読みたい本だけのとき「今年読んだ」を出さない（RecordsScreen の Jest）
- [ ] `getDateHint(status)`: `planned` は説明なし（`null`）、`in_progress` は「「読んでる」を選ぶと、読み始めた日に今日が入ります」、`completed` / `dropped` は終えた日に今日が入る旨。フォームは `null` のとき説明文を描画しない

## 画面・振る舞い

状態遷移（ステータス選択時にフォームの日付へ起きること）

| 切り替え先 | 読み始めた日 | 読み終えた日 |
|---|---|---|
| 読みたい | 空にする | 空にする |
| 読んでる | 空なら今日 | 空にする |
| 途中でやめた | 変えない | 空なら今日 |
| 読み終わった | 変えない | 空なら今日 |

- 日付エラー表示は、これまでどおりステータス切り替え時にクリアする
- 日付を空にしたあと、ユーザーが日付ピッカーで入れ直すのは自由（切り替え後の手入力は消えない）。保存時のステータスと日付の整合は強制しない
- 説明文はステータス選択の下に、選択中のステータスの分だけ出す。読みたいのときは出さない
- エラー時の追加の振る舞いはなし

## 設計

変更ファイル
- `app/src/lib/recordForm.ts` … `applyStatusChange` を上の表どおりにする
- `app/src/lib/yearCounter.ts` … `record.status !== 'completed'` を先にスキップ
- `app/src/lib/statusLabel.ts` … `getDateHint(status: RecordStatus): string | null`
- `app/src/components/RecordForm.tsx` … `getDateHint(values.status)` を使い、`null` なら描画しない
- テスト: `lib/__tests__/recordForm.test.ts`、`yearCounter.test.ts`、`statusLabel.test.ts`、`components/__tests__/RecordForm.test.tsx`、`screens/__tests__/RecordsScreen.test.tsx`、編集画面のテスト（既存の配置に合わせる）

データ構造の変更・新規ライブラリはなし。`getDateHint` の呼び出し元は `RecordForm.tsx` のみ（実装時に grep で確認）。

## テスト方針

- 状態遷移の表 → `applyStatusChange` の単体テスト（4 ステータス × 日付の有無）
- 再現手順 1〜6 → RecordForm / 編集画面の Testing Library テスト（ステータスを選び、日付欄の表示と保存内容を確認）
- 「今年読んだ」 → `countCompletions` 単体 + RecordsScreen の表示テスト
- 説明文 → `getDateHint` 単体 + フォームでの表示・非表示

## 判断ログ

1. **ユーザーが自分で入れた日付を消すか**
   - 選んだ案: ステータスに合わない日付は、自動入力かユーザー入力かを区別せず、切り替え時に消す。
   - 却下案: 自動入力された日付だけ消す（フォームに「自動入力フラグ」を持つ必要があり、編集で読み込んだ既存の日付との区別も複雑になる）。
   - 理由: 「読みたい本に読み終えた日がある」状態を作らないことが目的で、表のルールだけで決まるため単純で予測しやすい。誤操作で消えても日付ピッカーで入れ直せる。
2. **「途中でやめた」の日付**: 読み始めた日は残し、終えた日は空なら今日（今までどおり）。やめた日付は意味があるため。
3. **「今年読んだ」の数え方**: `completed` のみ（Issue の指定どおり。途中でやめた本は数えない）。
4. **保存時の強制クリアをしない**: 古いデータや将来の画面を巻き込むため。フォーム操作で整合させれば Issue の再現手順は解消する。
5. **説明文**: 読みたいは日付が入らないので出さない（`null`）。in_progress の説明を新設（実際に今日が入るので）。
