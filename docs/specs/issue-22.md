# Issue #22 手入力で追加するための動線が記録一覧画面に直接存在しない

## 背景・目的

Issue 本文は空で、タイトルのみ。現状の記録一覧画面（`RecordsScreen`）には「ISBN で探して追加」「バーコードで読み取って追加」のボタンが常時表示されているが、手入力で追加する動線は次の 2 つしかない。

- ナビゲーションヘッダー右の小さな「追加」テキスト（`src/app/(tabs)/_layout.tsx`）。目立たず、何を追加するのか分かりにくい。
- 0 件のときの空状態内の「記録を追加する」ボタン。記録が 1 件でもあると消える。

記録が存在する通常時に、画面内から手入力で追加する動線が直接見えない。他の 2 つの追加手段と並ぶ形で「手入力で追加」ボタンを記録一覧画面に常設し、3 つの追加方法が同列に見つけられるようにする。

## スコープ

### やること
- `RecordsScreen` の追加ボタン行に「手入力で追加」ボタンを追加する（記録 0 件・1 件以上のどちらでも表示）。押すと `/record/new`（空フォーム）へ遷移する。
- 3 ボタンが狭い幅でも読めるよう、ボタン行のレイアウトを調整する。

### やらないこと
- ヘッダー右「追加」ボタンの削除・変更（既存の `tabs.test.tsx` を維持）
- 空状態内の「記録を追加する」ボタンの変更（既存の挙動・テストを維持）
- 記録フォーム、ISBN 検索、バーコード画面の変更
- 新しいライブラリの追加（依存追加なし）

## 受け入れ条件

- [ ] 記録が 1 件以上あるとき、一覧画面に「手入力で追加」ボタン（role=button）が表示される
- [ ] 記録が 0 件のときも「手入力で追加」ボタンが表示される
- [ ] 「手入力で追加」を押すと `onAdd` が呼ばれる
- [ ] `(tabs)/index` 経由では押すと `/record/new` に遷移し、記録の追加フォームが表示される
- [ ] 「ISBN で探して追加」「バーコードで読み取って追加」、並び替え、行タップ、空状態の「記録を追加する」の既存挙動が変わらない
- [ ] `onAdd` 未指定でもボタン押下でクラッシュしない
- [ ] `pnpm check` が通る（カバレッジ・差分カバレッジを満たす）

## 画面・振る舞い

- 記録一覧画面の上部に、横並びのボタン行: 「手入力で追加」「ISBN で探して追加」「バーコードで読み取って追加」。その下に並び替え（1 件以上のとき）と一覧／空状態。
- 「手入力で追加」→ `onAdd()` → 親が `router.push('/record/new')`。クエリなしのため空フォームが開く。
- 状態遷移・エラー時の振る舞いの変更なし（ローディング中は従来どおりボタンを出さない）。

## 設計

変更ファイル:
1. `app/src/screens/RecordsScreen.tsx`
   - `lookupButtons` に `Pressable`（`accessibilityRole="button"`, `onPress={onAdd}`）で「手入力で追加」を先頭に追加。他 2 ボタンと同じ `lookupButton` スタイルを使う。
   - 3 ボタンが 1 行に収まらない場合に備え、`lookupRow` に `flexWrap: 'wrap'` を付与し、`lookupButton` に `minWidth`（例: 140）を設定。サイズ定数が他でも使われるなら `src/theme.ts` に定数化。
   - 変数名 `lookupButtons` は意味が広がるため `addButtons` に改名してよい。
2. `app/src/screens/__tests__/RecordsScreen.test.tsx`: テスト追加。
3. `app/src/__tests__/` の既存ルーター結合テスト（`tabs.test.tsx` など）に、一覧から「手入力で追加」を押して追加フォームが出るケースを追加。

`(tabs)/index.tsx` は `onAdd` で `/record/new` に遷移済みなので変更不要。状態管理・データ構造の変更なし。依存追加なし。

| CI 閾値 | `pnpm check` |

## 判断ログ

- **Issue 本文が空**: タイトルから「手入力で追加する動線を一覧画面内に直接置く」と解釈した。質問して止めるほどの曖昧さではなく（手戻りが小さい）、推測で進める。
- **ボタンを追加 vs FAB（右下の浮遊ボタン）**: 既存の追加ボタン行（ISBN／バーコード）と同列に並べる案を採用。理由: 既存 UI の慣習に合い、3 つの追加手段が同列に見つかる。FAB は新しいスタイルの導入と、リスト末尾との重なり対応が必要になるため却下。
- **ヘッダーの「追加」を置き換える vs 残す**: 残す。既存テストと既存の動線を壊さず、変更範囲を最小にするため。
- **空状態の「記録を追加する」**: 0 件時に「手入力で追加」と文言違いで 2 つ並ぶが、空状態の案内文脈では主要 CTA として有用なため残す。重複が気になる場合は別 Issue で整理する提案とする。
- **文言**: 既存ボタンの「〜で追加」に揃えて「手入力で追加」とした。
- **レイアウト**: 3 ボタンは狭い画面で窮屈になるため折り返し（`flexWrap`）を許可。縦積みや横スクロールは却下（実装が増える／操作性が落ちる）。
