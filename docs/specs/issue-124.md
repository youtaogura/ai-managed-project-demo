# Issue #124 見た目を直す: 振り返り

## 背景・目的

振り返り画面（`ReviewScreen`）が `docs/design-system/screens/review.png` と細かいところで違う。`cd app && pnpm shots -- review` で今の画面を撮り（`app/.screenshots/review.png`）、デザイン画像と見比べて違いを直す。画像と部品の README が食い違うときは部品の README を優先し、色・余白・角丸・文字は `design/tokens.ts` のトークンで直す。画像の本・数字・文章（サンプル）の違いは直さない。#117 で `Spine`/`Shelf` は直し済み（依存）。

## スコープ

### やること

実装担当は、撮影して下の「確認する項目」を1つずつ見比べる。仕様担当が画像と現行コードから推測した「差の候補」は次のとおり（撮って違いを確かめてから直す。違わなければ「一致」とする。下に無い差も見つけたら直す）。

| 項目 | 画像 | 現行コードからの差の候補 | 直す方向 |
|---|---|---|---|
| 見出し・期間 | 見出し左、期間 `2025/11 – 2026/10` が右・ベースライン揃え | 構成は同じ。余白・期間の文字を比べる | 違えば `space` / `label` で調整 |
| 3つの数字 | 3 枚のカード。ラベル（小）→数字（大）。カードに薄い枠線、角丸大きめ。「読んだ」は「48 冊」で単位つき | `surface1` 背景のみで枠線がない可能性 | カードに `colors.line` の枠線（1px）。数字・ラベルの文字スタイルを比べる。幅は均等 |
| 月ごとに読んだ本 | 12 列。1冊1段の積み上げ、各列の上に冊数（0 は出ない）、月ラベル、今月だけ墨・太め。下に注記 | 段の高さ・間隔・冊数の文字、今月ラベルの太さ | `BookStackChart` の段高・間隔・ラベルを画像に近づける（今月は `textPrimary`、ほかは `textSecondary`。太さは `value` 等のトークンから） |
| 今年のお気に入り | `Shelf` で背表紙を並べ、全幅の棚板 | `Shelf` の幅（`width - space[4]*2`）、上の余白。栞（#117 で直る） | 画像と比べ、違えば幅・余白を直す。`Shelf` 自体は #117 の範囲 |
| どうだった？ | 「平均」小ラベル＋大きい数字＋言葉（朱）。4 段の棒、最多だけ墨、ほかは灰（`textTertiary`）、棒の下地は薄い | 言葉（`ratings.word`）が墨（`value`）で朱でない。数字とラベルの大きさ | 言葉を `colors.ribbon` にするかは README を確認し、使ってよい場所でなければ判断ログに提案して残す。棒・ラベル・冊数の幅を比べる |

| セクションの区切りと余白 | セクション間が広く、見出しと中身の間は中程度 | `space[5]` / `space[3]` | 画像と比べて `space` から選ぶ |
| 空のとき | （画像なし） | — | 変えない |

### やらないこと
- `tokens.ts` / `docs/design-system/` / CI の変更。トークンに無い色・文字スタイルが要るときは判断ログに提案を書く
- 集計ロジック（`lib/review.ts`、`lib/analytics.ts`）の変更。表示される値・文言は変えない
- 振り返り以外の画面の見た目の変更。`Shelf` / `Spine` を直して他画面が変わる場合は、本棚・本棚を選ぶシート等も `pnpm shots` で撮って確かめ、PR 本文に書く（基本は #117 で済んでいるので、この Issue では `Shelf`/`Spine` を変えない方針）

## 判断ログ

- **差を仕様段階で確定しない**: この工程では撮影できない（アプリを起動しない）ため、画像と現行コードの読み合わせによる「差の候補」を列挙し、確認は実装担当の撮影に委ねる。却下案: 推測の数値まで仕様に固定する（誤りで手戻りになる）。
- **`Shelf`/`Spine` は変えない**: #117 で直す対象。この Issue の確認項目「お気に入りの棚」は、幅・余白の確認にとどめる。#117 が未マージでも、ここで共通部品を重ねて直さない。却下案: こちらでも `Shelf` を直す（#117 と衝突する）。
- **「まあまあ」の言葉の色（朱）**: README で `ribbon` を使える場所が「栞・書き出し・引用の線など決まった場所だけ」のため、勝手に使わない。画像では朱に見えるが、`docs/design-system/README.md` と `screens/README.md` を読んで許されていなければ墨のまま残し、ここに提案として追記する（実装担当が追記）。
- **枠線**: カードの枠線は `colors.line`（Chip README と同じ薄い線）を使う。新しい色は作らない。
- **集計・文言は変えない**: 見た目だけの Issue のため。期間の表記（`2025/11 – 2026/10`）は `summarizeReview` の出力のままで、画像との表記差があっても直さず「残した」と表に書く。
