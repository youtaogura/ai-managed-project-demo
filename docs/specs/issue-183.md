# Issue #183 読み返す画面に「読後メモ」の段を作り、直す・削除できるようにする

## 背景

#181 で記録のデータを「この本をひとことで」（`oneLiner`）と読後メモ（`postReadMemos`）に置き換え、#182 で読後メモを書く画面を作り直した。
読み返す画面（`screens/RereadScreen.tsx`）は、読後メモを見出しなしの罫線付きの文章として並べるだけで、件数も直す手段もなかった。
また一番下に、前の形の名残の「読後メモを書く」の行（元の「書き出しの続きを書く」）と、何も書いていない本だけに出る案内が別々にあった。

デザイン（`docs/design-system/screens/README.md` の「読み返す」「読み返す（読後メモなし）」「読後メモを直す」、`reread.png` `reread-empty.png` `memo-edit.png`）どおりに、

- 「この本をひとことで」と評価の下に、件数つきの「読後メモ」の段を作り、
- 読後メモを押すと「読後メモを直す」シートで直す・削除できるようにする。

まだリリースしていないので、保存データの移行・後方互換は考えない。

## 受け入れ条件

- [x] 「この本をひとことで」・評価の下に区切り線、「読後メモ」の段と件数（`N 件`）。読後メモを書いた順に `reading` の明朝・罫線付きで並ぶ。段の最後に点線の「＋ 読後メモを書く」（押すと読後メモを書く画面へ）（`RereadScreen.test.tsx`）
- [x] 読後メモが 0 件なら、段の中に案内（「読み終えた直後の言葉を残しておくと、あとで人に勧めるときに助けになります。…」）と「＋ 読後メモを書く」だけ（`RereadScreen.test.tsx`）
- [x] その下に「メモと引用」の段（今のまま）、一番下に「本棚」の行（`RereadScreen.test.tsx` の並びのテスト）
- [x] 「書き出しの続きを書く」（今の「読後メモを書く」の行）がない（`RereadScreen.test.tsx`）
- [x] 読後メモを押すと「読後メモを直す」シートが開く。上に本のタイトルと「閉じる」、見出し、全文の入った入力欄 1 つ、「保存する」、「この読後メモを削除」（`RereadScreen.test.tsx`）
- [x] 直して保存するとその 1 件だけが変わる。削除は確認してから消す（`RereadScreen.test.tsx`、`reread.test.ts`）
- [x] 読みたい本の画面（「読み始める」）には読後メモの段を出さない（`RereadScreen.test.tsx`）
- [x] `pnpm shots -- reread reread-empty memo-edit` で撮って画像と見比べる（下の「見た目の確認」）

## 設計

### 読み返す画面の組み（上から）

| 部分 | 中身 |
|---|---|
| 上部 | 今のまま（`BookHero`、「この本をひとことで」、星・数字・言葉・「お気に入り」） |
| 区切り線 + 読後メモ | 見出し「読後メモ」（`section-title`）と右に「N 件」（`label`・`text-secondary`）。N は本文が空白だけのものを除いた数 |
| 読後メモ（1 件以上） | `listPostReadMemos`（`createdAt` の順、同じなら保存の順）で並べる。1 件ずつ `RuledText` + `reading` の明朝。押せる（`accessibilityRole="button"`、ラベル「読後メモ ＋本文」）と「読後メモを直す」シート |
| 読後メモ（0 件） | 案内（`body`・`text-secondary`） |
| 「＋ 読後メモを書く」 | 「＋ メモ・引用を書く」と同じ点線のボタン（`borderStyle: dashed`、`text-tertiary` の枠、`radius-card`、高さ `touch-min` 以上）。押すと `onWrite`（`/write/[id]?from=reread`、ルートは変えない） |
| 区切り線 + メモと引用 | 今のまま |
| 読み始める（読みたい・途中でやめた本） | 今のまま |
| 区切り線 + 本棚 | 今のまま。その下の「読後メモを書く」の行はなくす |

- 読後メモの段は、読みたい本（`planned`）以外で出す（読んだ・途中でやめた）。読みたい本では、読後メモが残っていても出さない
- 前の「何も書いていない読了本だけに出す案内と『読後メモを書く』ボタン」は、読後メモの段の 0 件の表示に置き換えたのでなくす。そのため `lib/reread.ts` の `hasRereadContent` も使う場所がなくなり、消した

### 読後メモを直すシート（`components/PostReadMemoSheet.tsx`）

- `BottomSheet`（`showCloseButton` + `closeInTitleRow`）。上に本のタイトルと「閉じる」。メモ・引用を書くシートと同じ組み
- 見出し「読後メモを直す」: BottomSheet/README の「見出しは明朝、`screen-title` を 20px 程度に」に合わせ、`book-title` を BottomSheet の見出しと同じ大きさ（`TITLE_SIZE` / `TITLE_LINE_HEIGHT` を BottomSheet から export して共有）にする
- 入力欄 1 つ: `NoteSheet` の `FocusInput`（フォーカス中は枠が `text-primary`）を export して使う。文字は `reading` の明朝、面は TextField/README の `surface-1`、高さは `reading` の 6 行ぶん、余白 `space-4`。開くと全文が入り、シートが出る動きのあとにフォーカスし、カーソルを末尾に置く
- 主ボタン「保存する」: 本文が空白だけのときは押せない（判断ログ）。保存は `updatePostReadMemo(record, id, text)` → `repository.update`。本文は前後の空白を除く。`id` と `createdAt` は変えないので、並び順は変わらない
- 「この読後メモを削除」（`danger` の文字ボタン）: 押すとシートの中が確認（「この読後メモを削除しますか？」「元に戻せません。」、「キャンセル」「削除する」）に変わる。メモ・引用のシートと同じ形。確定で `removePostReadMemo(record, id)` → `repository.update`
- 失敗したら、シートの中にエラー（「保存できませんでした。…」「削除できませんでした。…」）を出し、入力を残す
- 「閉じる」・後ろのタップ・スワイプでは保存しない（直すシートなので下書きは持たない）

### 保存用の関数（`lib/reread.ts`）

- `updatePostReadMemo(record, id, text): NewRecordInput | null` — 本文が空白だけなら null
- `removePostReadMemo(record, id): NewRecordInput`
- どちらも `recordToInput` で他の項目（ひとこと・評価・メモ・引用・本棚など）をそのまま残し、`postReadMemos` だけ差し替える

### 撮影シーン

- `seed.cjs` の `makeRereadRecord` を reread.png に合わせる（10/1 – 10/20、4.2、読後メモ 3 件、メモ p.120 と引用 p.312）。同じデータを使う `shelf-pick` `memo-edit` `oneline-edit` もこの形になる
- `makeRereadEmptyRecord`（ソラリス、10/20 だけ、3.5、本棚なし、メモ p.88 だけ）を足し、`reread-empty` に使う
- `memo-edit` に、1 件目の読後メモの本文を押す操作（`{ text }`）を足し、「読後メモを直す」を待って撮る

## 判断ログ

| 判断 | 選んだ案 | 却下した案 | 理由 |
|---|---|---|---|
| 空（空白だけ）にして保存したとき | 「保存する」を押せなくする。消したいときは「この読後メモを削除」から | 空の保存を削除として扱い、同じ確認を出す | 「保存する」を押して消える（確認が出る）のは押した言葉と結果が違い、驚かせる。メモ・引用を直すシートも本文が空なら押せない（`isNoteSubmittable`）ので揃う。削除の入口は 1 つにしたほうが確認の出方もわかりやすい |
| 途中でやめた本の読後メモの段 | 出す（読みたい本だけ出さない） | 読み終えた本だけに出す | Issue は「読みたい本の画面には出さない」だけを指定。screens/README の読み返す画面は「読んだ・読みたい・途中でやめた本」を対象にし、メモ・引用の段も途中でやめた本には出している。途中でやめた理由を残したい人もいる。書く画面は状態を見ないので、そのまま使える |
| 読みたい本に読後メモが残っているとき | 出さない | 残っていれば出す（メモ・引用の段と同じ） | Issue の指示どおり。編集で読みたいに戻した本だけの例外で、データは消さないので、ステータスを戻せばまた出る |
| 0 件のときの案内の文 | 画像の文のまま「…助けになります。気になった文を選んで、続きを書くだけで大丈夫。」 | 「ヒントを選んで、…」に言い換える | screens/README は「…」で省略していて、続きは画像にしかない。書き方の決まり（「書き出し」「問い」と呼ばない）にも反しない。言い換えはデザインの持ち主に任せる |
| 前の「何も書いていない読了本の案内」と `hasRereadContent` | なくす | 残す | 読後メモの段の 0 件の表示が同じ役目（案内 + 読後メモを書く）を持つ。2 か所に出ると重なる |
| シートの作り | 新しい `PostReadMemoSheet` を作り、`FocusInput` は `NoteSheet` から export して共有 | `NoteSheet` に読後メモのモードを足す | `NoteSheet` はメモ／引用の切り替え・ページ・下書きを持ち、読後メモにはどれも要らない。分岐を増やすより小さな別の部品のほうが読みやすい。入力欄の見た目（フォーカスの枠）は共有して揃える |
| シートの見出しの書体・大きさ | 明朝（`book-title` を BottomSheet の見出しと同じ 20px） | 画像のゴシック太字、メモ・引用を直すシートと同じ `section-title`（14px） | BottomSheet/README が「見出しは明朝、20px 程度」。画像と README が違うときは README を優先する（AGENTS.md）。メモ・引用を直すシートの見出しは今回は変えない（範囲外） |
| 入力欄の面 | `surface-1`（シートと同じ面、枠で区切る） | 画像の色（`bg` に近い）、メモ・引用のシートの `surface-2` | TextField/README が「入力欄は面 `surface-1`」。README を優先した |
| 削除の確定の触覚 | 付けない | 付ける | ブランドブックは「削除の確定」に触覚とするが、メモ・引用の削除にも付いていない。揃えるなら別 Issue で両方に付ける |
| `makeRereadRecord` のメモと引用 | 画像に見える 2 件（メモ p.120、引用 p.312、ひとことなし）にする | 画像の件数表示「3 件」に合わせて 3 件にする | 画像は「3 件」なのに 2 件しか描いていない。見えている中身に合わせ、件数は実データの 2 件になる |
| 消したテスト | `RereadScreen.test.tsx`: 「completed では書いてある本でも『読後メモを書く』の行を出す」「completed 以外では行も案内も出さない」「何も書いていない completed の本では案内とボタン」「何も書いていなくても completed 以外では案内を出さない」「引用・メモだけの読了本では『何も書いていません』を出さない」「感想が空なら感想の段を出さない」、`reread.test.ts`: `hasRereadContent` の 3 つ | — | 一番下の行・前の案内・`hasRereadContent` をなくしたため。代わりに、点線のボタンと onWrite、0 件の案内とボタン、行がないこと、読みたい本に段がないこと、段の並びを確かめるテストを足した |
