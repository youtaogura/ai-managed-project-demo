# ほんのめも

ほんのめもは、本を読み終えた直後の感動を、自分の言葉で残して人に伝えるための読書記録アプリのデザインシステム。**生成りの紙と明朝体の静かな書斎に、布装の背表紙が並ぶ。** 主役は書影ではなく、自分の言葉と背表紙の棚。

アプリ名は「ほんのめも」。デザインの方向性の名前は「書斎」（下の「案1 書斎」）で、部品や画面の説明に出てくる「書斎」はこの方向性を指す。方針の元になった文書は「読書記録アプリ 価値の定義と方向転換」（Doc）。

> **読後の新鮮な感動を、そのまま人に伝えたい人のためのアプリ。**

## このフォルダについて

- **このフォルダがデザインシステムの正本。** 人間だけが変更する（`orchestrator/policy.json` の保護対象）。変更は PR で行う。
- トークンの値は `tokens.json`。アプリのコードは、ここから生成した `app/src/design/tokens.ts` を使う。`tokens.json` を変えたら `node .github/scripts/gen-design-tokens.mjs` で生成し直し、両方を同じ PR に含める（CI が一致を検査する）。
- 部品ごとの決まりは `components/<部品名>/README.md`。
- 画面ごとのデザイン（画像と説明）は `screens/README.md`。
- 元データは claude.ai のデザインキャンバスの「読後ノート 全画面（案1）」ページ。方向性を決めたときの3案は「読後ノート 3案」ページにある。採用したのは **案1 書斎**。
- 前のデザインシステム「Shelf Theater」（暗い地で書影が主役）は廃止した。トークンの名前は互換のために残し、値を書斎のものに置き換えている。「廃止予定」と書いたトークンと部品は、画面を作り替えたら消す。

## 原則

迷ったら上の原則を優先する。

1. **自分の言葉が主役**: 画面でいちばん大きく、いちばん良い書体で組むのは、ユーザーが書いた言葉（この本をひとことで、読後メモ、引用）。UI の文字は控えめにする
2. **読み返すために組む**: 記録は、あとで人に勧めるときに 30 秒で思い出せるように組む。書いた順ではなく、読む順に並べる
3. **書かせない、続きを書かせる**: 白紙の感想欄だけにせず、書き始めの「ヒント」（「いちばん心に残ったのは、」など）を差し出す。使うのも使わないのも自由
4. **背表紙の棚で積み上げる**: 本は背表紙で並べる。書影がなくても、棚が埋まっていく様子で積み上がりを見せる
5. **紙と墨と朱**: 色は、紙（地）・墨（文字と主ボタン）・朱（栞と特別な印）と、背表紙の色だけ。足さない
6. **削る勇気**: 迷ったら足さない。遊びの飾りも、意味がはっきりしているものだけ

## 色

- 地は `bg`（生成りの紙）。カード・シート・入力欄は `surface-1`（明るい紙）、控えめな面は `surface-2` の2段。
- 文字は `text-primary`（墨）/ `text-secondary` / `text-tertiary` の3段。`text-tertiary` は `bg` と `surface-1` の上だけで使う。
- **主ボタン・選択中のチップ・評価の星は `accent`（墨）**、その上の文字は `accent-ink`（紙）。
- **朱 `ribbon` は特別な場所だけ**: お気に入りの栞、引用の左の線、選択中のタブの下線、評価の言葉、トグルのオン。1画面に数か所まで。
- 背表紙の色は `spine-1`〜`spine-10`。タイトルは `spine-ink`（どの背表紙の上でも 4.5:1 以上）。本を登録するときに選べて、初期値は順に割り当てる。
- 本棚の棚板は `shelf-board`。その下にだけ影（`shadow-cover`）を付ける。
- `danger` は取り消せない操作の文字と枠だけ。赤い面は作らない。
- 今はライトテーマのみ。ダークテーマは、必要になったら同じトークン名で値を足す。

## 文字

- **UI は `sans`（Noto Sans JP）**: ボタン、ラベル、チップ、設定、説明文。太さは 400 / 700 / 900。
- **本と自分の言葉は `serif`（しっぽり明朝）**: 画面タイトル（`screen-title`）、本のタイトル（`book-title`）、この本をひとことで（`one-line`）、読後メモ（`reading`）、引用（`quote`）、背表紙（`spine-title`）。太さは 600 / 800（読み込んでいるのはこの2つ）。
- 読後メモは `reading` の明朝で組む。ヒントから入れた文も、ユーザーが書いた文章の一部として同じ見た目にする（朱や太字で区別しない）。
- 読み返す画面の本文は、行の高さ 32px の罫線（`line`）を引いて、ノートに書いたように見せる。
- 数字は `display-number`。10.5px（`micro`）より小さい文字は使わない。

## 余白と形

- 左右の余白は、本棚が `space-4`（16px）、一覧・設定が `space-5`（20px）、読む画面（続きを書く、読み返す）が `space-6`（24px）。
- 背表紙は角をほぼ立てる（`radius-thumb` 2px、上の角だけ）。カード・入力欄・ボタンは `radius-card`（12px）、シートは `radius-sheet`（20px）、チップとトグルは `radius-full`。
- タップできるものは `touch-min`（44px）以上。横長のボタンは `button-height`（48px）。
- 影は棚板の下だけ。カードは枠線（`line`）で区切り、影は付けない。

## 背表紙と本棚

- 背表紙の幅は `spine-width-min`〜`spine-width-max`（28〜44px）、高さは `spine-height-min`〜`spine-height-max`（150〜184px）。本ごとにばらつかせて本棚らしく見せる（同じ本はいつも同じ大きさ。本の ID から決める）。
- タイトルは縦書き（`writing-mode: vertical-rl` 相当）で、上から組む。長いタイトルは途中で切る。
- **飾りはお気に入りの栞だけ**: 背表紙の上から朱の栞が垂れる。ステータス（読んでる・読んだ・読みたい）で見た目は変えない。
- 棚板の上に、下揃えで並べる。棚1段の幅に収まる数で折り返す。

## 書き方

- 画面の文言は短く、やわらかく。「評価」「問い」「感想を入力」のような堅い言葉を使わない。
  - 評価は「どうだった？」と聞き、点数に言葉を添える: 5.0「最高」、4.0〜4.9「よかった」、3.0〜3.9「まあまあ」、2.9 以下「あんまり」
  - 読み終えたあとに書く感想は「**読後メモ**」。書き始めの手がかりは「**ヒント**」（例: 「いちばん心に残ったのは、」）。「問い」「お題」「書き出し」とは呼ばない
  - 読み終えたあとの主ボタンは「記録を書く」
- ステータスは「読みたい」「読んでる」「途中でやめた」「読み終わった」。漫画も本として扱い、区別しない。
- 「お気に入り」は、人に勧めたい本・特別な本の印。

## 動きと触覚

- 動きは短く物理的に。150〜300ms、ばねのような減速。
- 触覚フィードバックは、読み終えたとき、評価の整数の境目、削除の確定だけ。
- 端末の「動きを減らす」設定がオンなら、移動を伴う動きを止めてフェードだけにする。

## アイコン

- 線のアイコン。線幅 1.6〜1.8px、端と角は丸める。塗りのアイコンは星と栞だけ。
- アイコンだけのボタンには、読み上げ用のラベルを必ず付ける。

## 実装（React Native）

- トークンは `app/src/design/tokens.ts`（`tokens.json` から生成。手で編集しない）を使う。名前はキャメルケースになる（`text-primary` → `colors.textPrimary`、`spine-3` → `colors.spine3`、`space-5` → `space[5]`、`radius-card` → `radius.card`、`touch-min` → `size.touchMin`）。
- 文字は `AppText` の `variant` にトークンの文字スタイル名を渡す（明朝のスタイルは自動で明朝のフォントになる）。
- 画面や部品に色・余白・角丸の値を直接書かない。`app/src/theme.ts` は既存の画面との互換のための層。
- 部品は `components/` の決まりに合わせて作る。
- デザインシステムにない色や部品が必要になったら、勝手に足さず、仕様書の判断ログに提案として書く。
