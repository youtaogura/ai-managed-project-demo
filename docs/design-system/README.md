# Shelf Theater

Shelf Theater は、読んだ本・漫画と、見た映画・ドラマ・アニメを記録するアプリのデザインシステム。**暗い劇場のような画面で、書影とポスターだけが色を持つ。** アプリ側は黒と白に徹し、作品の色を主役にする。

「Shelf Theater」は仮の名前。アプリ名が決まったら置き換える。方針の元になった文書は「読書・視聴記録アプリ デザイン方針」（Doc）。

## このフォルダについて

- **このフォルダがデザインシステムの正本。** 人間だけが変更する（`orchestrator/policy.json` の保護対象）。変更は PR で行う。
- トークンの値は `tokens.json`。アプリのコードは、ここから生成した `app/src/design/tokens.ts` を使う。`tokens.json` を変えたら `node .github/scripts/gen-design-tokens.mjs` で生成し直し、両方を同じ PR に含める（CI が一致を検査する）。
- 部品ごとの決まりは `components/<部品名>/README.md`。
- 画面ごとのデザイン（画像と説明）は `screens/README.md`。
- 見た目の確認用に、claude.ai のデザインシステム「Shelf Theater」（部品のライブプレビュー付き）がある。正本を変えたら、そちらも更新する。
- 方向性を決めたときのデザイン案（案 A〜C と B の配色案）は、claude.ai のデザインキャンバス「記録アプリ デザイン3案（一覧・詳細）」にある。採用したのは **B-1 モノクロ**。

## 原則

迷ったら上の原則を優先する。

1. **画像が主役**: 画面の面積の多くを書影・ポスター・自分で撮った写真に使う。文字は画像を補う程度にとどめる
2. **すぐ記録できる**: 読み終えた本を3タップほど・10秒以内で記録できる。必須でない項目は後回しにする
3. **触って気持ちいい**: すべての操作に即座に反応を返す。要所では動きと触覚フィードバックも使う
4. **積み上がりを見せる**: 記録が増えるほど一覧が豊かになる。数字より、画像がたまっていく様子で伝える
5. **削る勇気**: 迷ったら足さない
6. **画像がなくても美しい**: 書影のない記録が混ざっても一覧の美しさを崩さない

## 色

- 地は `bg`（ほぼ黒）。面は `surface-1`（画面端に固定されるもの）と `surface-2`（セルとボタン）の2段だけ。
- **アクセントは `accent`（白）だけ。** 記録ボタン、今年の作品数、評価の星、選択中のタブ、編集ボタンに使う。有彩色のアクセントは足さない。色は書影が持つ。
- 文字は `text-primary` / `text-secondary` / `text-tertiary` の3段。`text-tertiary` は `bg` の上だけで使う。
- `danger` は取り消せない操作の文字と枠だけ。赤い面は作らない。
- 書影・ポスターの上に置くボタンは `scrim` の面にする。
- 今はダークテーマのみ。ライトテーマは、必要になったら同じトークン名で値を足す。

## 文字

- UI は `sans`（Noto Sans JP、端末ではヒラギノ角ゴ / Noto Sans JP にフォールバック）。太さは 400 / 700 / 900 の3つ。
- **数字は大きく太く**（`display-number`）。評価と今年の作品数は、見た瞬間に分かる大きさにする。
- **明朝体（`serif`）は「文字の表紙」だけ**に使う。UI の見出しには使わない。
- 本文 14px・行の高さ 24px。10px（`micro`）より小さい文字は使わない。

## 余白と形

- 左右の余白は、一覧が `space-5`（20px）、詳細が `space-6`（24px）。
- 要素同士は `space-2`〜`space-4`。グリッドの書影の間隔は 10px（`space-2` と `space-3` の間。書影を詰めて本棚らしく見せる）。
- 書影の角丸は小さく（`radius-thumb` 6px、大きいカードは `radius-card` 10px）。実物の本やポスターに近づける。
- タップできるものは `touch-min`（44px）以上。横長のボタンは `button-height`（48px）。
- 影は `shadow-cover` だけ。書影を浮かせたい詳細画面などで使い、一覧のグリッドには付けない。

## 画像（書影・ポスター・写真）

- 縦横比は 2:3 に揃える。本（実物は約 1:1.42）も 2:3 の枠に収め、はみ出しは中央で切り抜く。一覧の格子が揃うことを優先する。
- 表示の優先順は「自分で撮った写真 → 書影・ポスター → 文字の表紙」。
- **文字の表紙**: 画像がない記録は、種別ごとの色（`cover-<種別>-bg` / `cover-<種別>-ink`）の地に、タイトルを明朝体で組んで表紙を作る。種別は本・漫画・映画・ドラマ・アニメ。大きさに応じて `cover-title-hero` / `cover-title-card` / `cover-title-thumb` を使う。
- 画像の上に文字を重ねない（タイトルは画像の外に置く）。例外は文字の表紙と、詳細画面の上部。

## 動きと触覚

- 動きは短く物理的に。150〜300ms、ばねのような減速。
- 一覧から詳細へは、書影がそのまま拡大してつながる動きを目指す（実装できなければ、書影のフェードと拡大で代える）。
- 触覚フィードバックは、記録の完了、星の整数の境目、削除の確定だけ。常には鳴らさない。
- 端末の「動きを減らす」設定がオンなら、移動を伴う動きを止めてフェードだけにする。

## アイコン

- 線のアイコン。線幅 1.6〜1.8px、端と角は丸める。塗りのアイコンは星と状態の点だけ。
- アイコンだけのボタンには、読み上げ用のラベルを必ず付ける。

## 書き方

- 画面の文言は短く、ユーザーの言葉で。「記録する」「読み終わった」「見てる」。
- ステータスは本・漫画で「読」、映画・ドラマ・アニメで「見」を使い分ける（「読みたい／見たい」「読んでる／見てる」「途中でやめた」「読み終わった／見終わった」）。
- 祝う言葉はさりげなく。節目（10・50・100作品）だけ少し大きくする。

## 実装（React Native）

- トークンは `app/src/design/tokens.ts`（`tokens.json` から生成。手で編集しない）を使う。名前はキャメルケースになる（`text-primary` → `colors.textPrimary`、`space-5` → `space[5]`、`radius-card` → `radius.card`、`touch-min` → `size.touchMin`）。
- 画面や部品に色・余白・角丸の値を直接書かない。`app/src/theme.ts` は既存の画面との互換のための層で、新しいトークンを参照する形に移行していく。
- 部品は `components/` の決まりに合わせて作る。部品ごとの README に、受け取る値と状態を書いている。
- デザインシステムにない色や部品が必要になったら、勝手に足さず、仕様書の判断ログに提案として書く。
